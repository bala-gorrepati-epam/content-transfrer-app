# Operation reference: content transfer

Derived from the installed types in `node_modules/@sitecore-marketplace-sdk/xmc/dist/xmc/src/client-content-transfer/` (`ContentTransfer` namespace). Installed types win on any conflict.
Errors common to all operations: 400 invalid ids or params, 401 invalid token, 403 missing role.

Each section lists: environment, method, route, params, response, and notes.

---

## 1. createContentTransfer

- Environment: SOURCE
- Method: `client.mutate`
- Route: POST `/content/v1/transfers`. Success: 202, no body (the transfer is built asynchronously; poll operation 2).

Params:
- `query.sitecoreContextId?: string` (source)
- `body.transferId: string` (required, generated by us)
- `body.configuration.dataTrees?: Array<{ itemPath?: string; scope?: Scope; mergeStrategy?: MergeStrategy }>`
  - `itemPath`: existing item path in the source environment, master database.
  - Casing is camelCase. A Postman sample used PascalCase; ignore it.

```ts
const transferId = crypto.randomUUID();
await client.mutate("xmc.contentTransfer.createContentTransfer", {
  params: {
    query: { sitecoreContextId: sourceContextId },
    body: {
      transferId,
      configuration: {
        dataTrees: selectedItems.map((item) => ({
          itemPath: item.path,
          scope: item.scope,
          mergeStrategy: item.mergeStrategy,
        })),
      },
    },
  },
});
```

## 2. getContentTransferStatus

- Environment: SOURCE
- Method: `client.query`
- Route: GET `/content/v1/transfers/{transferId}/status`. Success: 200.

Params:
- `path.transferId: string`
- `query.sitecoreContextId?: string` (source)

Response body (PascalCase):
```ts
{
  State: string; // e.g. "Completed"
  ChunkSetsMetadata: Array<{
    ChunkSetId: string;
    ChunkCount: number;
    TotalItemCount: number;
  }>;
}
```

Notes:
- Poll until `State` is `Completed`. Treat an unknown, non-progress state as a failure and show the raw `State`.

```ts
const status = await client.query("xmc.contentTransfer.getContentTransferStatus", {
  params: {
    path: { transferId },
    query: { sitecoreContextId: sourceContextId },
  },
});
const body = status.data?.data; // { State, ChunkSetsMetadata }
```

## 3. getChunk

- Environment: SOURCE
- Method: `client.query`
- Route: GET `/content/v1/transfers/{transferId}/chunksets/{chunksetId}/chunks/{chunkId}`. Success: 200, body is `Blob | File`.

Params:
- `path.transferId: string`
- `path.chunksetId: string` (lowercase "s" in `chunksetId`)
- `path.chunkId: number`
- `query.sitecoreContextId?: string` (source)

Response:
- The body is binary. Keep it as a `Blob` and pass it unchanged to saveChunk (operation 4).
- The `Content-Disposition` header carries the media flag saveChunk needs, for example `form-data; ItemsProcessed=1; ItemsSkipped=0; IsMedia=false`. `IsMedia` is `true` or `false`.
- Read the header from the raw response, `result.data.response.headers`, not from the body.

Notes:
- Check `blob.size > 0`. An empty Blob means the body was not returned.

```ts
const chunk = await client.query("xmc.contentTransfer.getChunk", {
  params: {
    path: { transferId, chunksetId, chunkId },
    query: { sitecoreContextId: sourceContextId },
  },
});
const blob = chunk.data?.data;
const disposition = chunk.data?.response.headers.get("Content-Disposition") ?? "";

// Fail when the value is missing. Do not default to false.
const match = /(?:^|;)\s*IsMedia\s*=\s*(true|false)\s*(?:;|$)/i.exec(disposition);
if (!match) throw new Error("getChunk response has no IsMedia value");
const isMedia = match[1].toLowerCase() === "true";
```

## 4. saveChunk

- Environment: DESTINATION
- Method: `client.mutate`
- Route: POST `/content/v1/transfers/{transferId}/chunksets/{chunksetId}/chunks/{chunkId}`. Success: 201, no body.

Params:
- `body: Blob | File` (the chunk from operation 3)
- `path.transferId: string`
- `path.chunksetId: string`
- `path.chunkId: number`
- `query.isMedia?: boolean` (default false). Use the `IsMedia` value from the same chunk's getChunk response (see operation 3).
- `query.sitecoreContextId?: string` (destination)

```ts
await client.mutate("xmc.contentTransfer.saveChunk", {
  params: {
    path: { transferId, chunksetId, chunkId },
    query: { sitecoreContextId: destinationContextId, isMedia },
    body: blob,
  },
});
```

Save every chunk of every chunk set before step 5.

## 5. completeChunkSetTransfer

- Environment: DESTINATION
- Method: `client.mutate`
- Route: POST `/content/v1/transfers/{transferId}/chunksets/{chunksetId}/complete`. Success: 200.

Params:
- `path.transferId: string`
- `path.chunksetId: string`
- `query.sitecoreContextId?: string` (destination)

Response body (PascalCase):
```ts
{ ContentTransferFileName: string }
```

Notes:
- Several chunk sets produce several files. Keep each returned name for steps 6 and 7.

```ts
const done = await client.mutate("xmc.contentTransfer.completeChunkSetTransfer", {
  params: {
    path: { transferId, chunksetId },
    query: { sitecoreContextId: destinationContextId },
  },
});
const fileName = done.data?.ContentTransferFileName;
```

## 6. consumeFile

- Environment: DESTINATION
- Method: `client.query`
- Route: `/items/v2/ConsumeFile`. Success: 202, no body (asynchronous; check with operation 7).

Params (all in `query`, no path or body):
- `query.databaseName: string` (required, e.g. `master`)
- `query.fileName: string` (required). The `ContentTransferFileName` from operation 5 with a `blob://` prefix.
- `query.sitecoreContextId?: string` (destination)

```ts
await client.query("xmc.contentTransfer.consumeFile", {
  params: {
    query: {
      databaseName: "master",
      fileName: `blob://${contentTransferFileName}`,
      sitecoreContextId: destinationContextId,
    },
  },
});
```

## 7. getBlobState

- Environment: DESTINATION
- Method: `client.query`
- Route: `/items/v2/GetBlobState`. Success: 200.

Params:
- `query.fileName: string` (required). The plain `ContentTransferFileName` from operation 5, without the `blob://` prefix that operation 6 uses.
- `query.sitecoreContextId?: string` (destination)

Response body (observed on a real run; PascalCase):
```ts
{
  BlobState: string;    // e.g. "Consumed"
  Error: unknown;       // null when consuming has not failed
  ConsumedName: string; // e.g. "consumed.<timestamp>.<guid>"
  Actions: { Details: string }; // relative URL of the status details page
}
```

Notes:
- The installed types declare `status` and `details` (lowercase) for this response. They do not match the real API. Use the observed shape above and type it in our own code.
- Done when `BlobState === "Consumed"`. A non-null `Error` is a failure; show it.
- Any other `BlobState` keeps polling until the timeout.

```ts
const state = await client.query("xmc.contentTransfer.getBlobState", {
  params: {
    query: { fileName: contentTransferFileName, sitecoreContextId: destinationContextId },
  },
});
const body = state.data?.data;
```

Params:
- `path.transferId: string`

```ts
await client.mutate("xmc.contentTransfer.deleteContentTransfer", {

    path: { transferId },

  },
});
```
